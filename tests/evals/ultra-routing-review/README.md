# Ultra routing and review completion

`fixture.py prepare --source <checkout> --output <new-directory>` creates seven isolated Git fixtures using the candidate Ultra instructions. Run each `prompt.txt` with a real model in that fixture's working directory, then run `fixture.py grade --output <case-directory> --transcript <run.jsonl>`. Preserve prompts, JSONL execution evidence, source.json, model/settings, and grader output under local `.evals/`.

The implementation and review-only cases start at the post-review checkpoint with an independent finding and an executable pricing contract. They test coordinator consumption of existing evidence, not reviewer quality or native TDD. The explicit wrapper case substitutes only the solve backend with a sentinel; it tests dispatch, not Claim or Solve Record behavior. Alias cases substitute small compatible target skills with observable artifacts and an exclusive fixture inventory; they test current-only, legacy-only, and missing installations without changing global skills. The unrelated request must leave the reviewed source unchanged and never enter solve.

Grade artifact state, not response phrasing. Inspect execution logs as well: a missing dependency must be reported, and an alias success must read the selected skill before producing its artifacts. No tools/model host is implied tested merely by generating fixtures. Run `bash tests/ultra-routing-review.sh` to validate metadata and prove the coordinator graders reject unrepaired implementation and modified review artifacts without calling a model. Model runs are opt-in, outside CI.
